# Dead Code Scan

Static analysis of the `tdns-stats` repository. The CSS/HTML items below were confirmed and
subsequently removed on 2026-11-09; the `/api/servers` route was deferred then and removed
later during the Phase B backend cleanup. Each finding lists
the exact location and the evidence that proves it was unreferenced. Removals were verified in
a live headless-browser run: 0 computed/layout differences and byte-identical screenshots
against the pre-change stylesheet.

The project has no build step or bundler; the frontend modules are plain `<script>` globals
(`window.Charts`, `window.Selection`, `window.Log`, ...). References were checked both as
literal tokens and as dynamically assembled class strings.

## Definition used here

"Dead code" means code that is **never executed** or markup/CSS that is **never applied or
consumed**. A function that is called internally within its own module is **live**, even if
nothing outside the module imports it. An export that no consumer reads is a *redundant
export*, not dead code, and is listed separately below.

## Truly dead

### 1. `GET /api/servers` route is never called

- **Location:** `backend/src/server.js` (route handler; removed)
- **What:** Returned `{ name, url }` for every configured server.
- **Why it is dead:** A repository-wide search for `api/servers` finds only the route
  definition. The frontend fetches every other API it uses (`/api/session`, `/api/stream`,
  `/api/config`, `/api/watch-server`, `/api/cache/search`, `/api/block-list-stats`,
  `/api/version`, `/api/updates/*`, `/api/health`, `/api/changelog`) but never `/api/servers`.
  Server metadata is instead delivered through `/api/config`. No test, script, README, or
  config file references the endpoint.
- **Caveat:** if an out-of-repo consumer calls this endpoint, it is not dead. Within this
  repository it is unreachable.
- **Safe to remove:** yes (repo-internal).
- **Status:** removed — the route handler was deleted from `server.js`; server metadata is
  still served through `/api/config`, so no client lost a capability.

### 2. Unused CSS rules

These selectors are defined in `frontend/css/style.css` but never applied. They are not
generated by string concatenation either (a search for the substrings across `frontend/js`
and `frontend/index.html` returns only the CSS definitions).

| Selector | Location (pre-removal) | Evidence |
| --- | --- | --- |
| `.toggle-label` (and `.toggle-label input`) | `style.css:435-436` | No `toggle-label` token in any JS/HTML file. |
| `.srv-stats-grid--wide` | `style.css:465`, `:1159` | JS only builds `srv-stats-grid` and `srv-stats-grid--rtt` (`app.js:1628,1654`); no `--wide` anywhere. |
| `.cluster-agg-card` | `style.css:468` | No `cluster-agg` token in any JS/HTML file. |
| `.blocked-lookup-row` (and span rule) | `style.css:812-821` | The live row class is `blocked-lookup-meta-row` (`app.js:1136`); bare `blocked-lookup-row` appears nowhere. |

- **Safe to remove:** yes, all four rule blocks. Check `.cluster-agg-card` and
  `.srv-stats-grid--wide` against any planned/uncommitted work before deleting.
- **Status:** removed (2026-11-09) — all four rule blocks deleted from `style.css`.

### 3. CSS custom property `--accent-pink-bg` is unused but retained for consistency

- **Location:** `frontend/css/style.css:39` (dark theme), `:74` (light theme)
- **Why it was flagged:** The value is only ever *defined*. There is no `var(--accent-pink-bg)`
  anywhere. (By contrast, `--accent-pink` at `:38,:73` *is* consumed by
  `frontend/js/charts.js:257`.)
- **Decision:** kept. Every other accent colour (`blue`, `green`, `red`, `yel`, `pur`, `teal`,
  `ora`, `slate`) has a `-bg` companion and all of them are used, so the pink `-bg` token is
  intentionally retained for palette consistency even though nothing consumes it yet.

### 4. Dead `id="mainTabs"` attribute

- **Location:** `frontend/index.html:27` (`<nav class="main-tabs" id="mainTabs">`)
- **Why it is dead:** The `mainTabs` identifier appears nowhere else — not in CSS, JS,
  `getElementById`, `querySelector`, or `aria-*` references. The element is styled and
  manipulated through the `main-tabs` class instead.
- **Safe to remove:** yes — delete just the `id` attribute; keep the class.
- **Status:** removed (2026-11-09) — the `id` attribute was deleted; `class="main-tabs"` kept.

## NOT dead — redundant exports only

These functions are **called within their own module**, so they are live code. The only
issue is that nothing outside the module reads the exported name. This is a minor API-surface
cleanup, **not dead code**, and removing the functions would break internal callers.

### `backend/src/technitium.js` — 5 redundant export entries

Exported at `technitium.js:886`, but not imported by either consumer
(`poller.js:3`, `server.js:15`). Each is used internally, so the function must stay:

| `isLoopbackClient` | `:626` | `:755` |

**Status:** removed (2026-11-09) — the five keys were dropped from `module.exports`; functions kept.
`listsFromReportTexts` was also renamed to `listsFromReportStrings`, with its caller-local
arrays renamed `texts` → `reportStrings` for clarity.

### `frontend/js/selection.js` — redundant `clearAll` export

`clearAll` is defined at `:49` and called internally at `:178`, `:209`, `:214`. Only the
return-object entry at `:414` was unused (`Selection.clearAll(...)` is never called).

**Status:** removed (2026-11-09) — `clearAll` was removed from the returned object literal; the function is kept.

## Investigated and confirmed NOT dead

- **`Charts.setLoadCallback` / `loadCallback`** — live. Implemented at `charts.js:300`
  (stores the fn on `window.loadChartHiddenState`), read at `charts.js:221-222`, wired from
  `app.js:2507`.
- **`.feed-latencytype`** — live. Emitted in `feed.js:227`; styled at `style.css:987`,`:1220`.
- **`.feed-type.noerror` / `.feed-type.other`** — live. Badge classes are built dynamically as
  `badgeText.toLowerCase().replace(/\s+/g, '')` at `feed.js:207`, which yields `noerror` and
  `other`.
- **`Log.enable` / `Log.disable` / `Log.isEnabled`** — not dead. Intentionally exposed for the
  browser dev console (comment at `log.js:3-4`). Application code only calls `Log.debug`.
- **`rttHistoryToSeries(map)`** — the parameter *is* used (`poller.js:29`, `map.entries()`);
  the earlier unused-parameter suspicion was a false positive.
